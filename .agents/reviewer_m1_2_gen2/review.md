# Quality Review Report

**Verdict**: REQUEST_CHANGES

## Review Summary

While the follow-up requirements (R1, R2, R3) have been largely implemented and the manual verification scripts (`audit_empty.js` and `verify-all-chapters.js`) complete with zero issues, an in-depth review of the modified codebase and a thorough investigation of the test failures in the E2E test suite (`tests/run-e2e.js`) have revealed major logic bugs in the parsing implementation that prevent required content from rendering.

Specifically, the "En lien avec" group headers in the "Situations de départ" sections are completely filtered out and missing from the output. Additionally, the first section headers in prepended pages (from boundary shifting) are skipped and eaten by the parser because the preamble state is not yet triggered.

---

## Findings

### [Major] Finding 1: "En lien avec" Group Headers Filtered Out
- **What**: The group headers (e.g., `En lien avec la définition et avec le diagnostic :`) are missing from the rendered HTML output.
- **Where**: `app.js` lines 481, 490, and 606.
- **Why**: 
  - Requirement R3 states that the Situations de départ parser must retain group headers (e.g. lines starting with `En lien avec`).
  - In `app.js`, a specific case was added inside the lines loop:
    ```javascript
    if (/^En lien avec/i.test(l)) {
      html += `<li class="sit-group-title">${esc(l)}</li>`;
      continue;
    }
    ```
  - However, in step 4 (the initial line filtering step), line 481 contains:
    ```javascript
    if(/^En lien avec/.test(l))return false;
    ```
    This filters out all lines starting with "En lien avec" from the `lines` array before the loop can ever see them.
  - Furthermore, in the `firstSec` filter on line 490, there is no bypass rule to keep "En lien avec" lines if they are encountered before the first section, which would also filter them out.
- **Suggestion**: 
  1. Remove `if(/^En lien avec/.test(l))return false;` from the initial filters on line 481.
  2. Add a bypass rule in the `firstSec` filter (line 490) to prevent filtering out "En lien avec" lines:
     ```javascript
     if(/^En lien avec/i.test(l)) return true;
     ```

### [Major] Finding 2: Prepended Chapter Section Headers Discarded
- **What**: When pages are shifted from chapter $i$ to chapter $i+1$ via the preprocessor, if the shifted block starts with a section header (e.g. `I. Généralités`), it is completely discarded and missing from the output.
- **Where**: `app.js` line 668:
  ```javascript
  const secM=l.match(SECTION_RE);
  if(secM){
    if(!pastPreamble)continue;
  ```
- **Why**: 
  - The variable `pastPreamble` starts as `false`. Section headers matching `SECTION_RE` are skipped with `continue` if `pastPreamble` is `false`.
  - At the start of a chapter, `pastPreamble` remains `false` until a sub-heading (matching `LETTER_RE`), a definition block, or regular prose is encountered.
  - When pages are prepended (such as the start of Chapter 13 "Alitement" containing `I. Généralités` followed by `A. Définition`), the main section header `I. Généralités` is processed first while `pastPreamble` is `false`, so it is skipped and lost.
- **Suggestion**:
  - The preamble phase should be terminated (setting `pastPreamble = true`) when a valid section header is encountered, rather than skipping it. Or, initialize `pastPreamble = true` if the chapter content starts directly with a section header without any preamble metadata.

### [Minor] Finding 3: Outline Panel Uses Pre-Clean Section Count
- **What**: The outline panel (`ch-outline`) is rendered containing sections that are subsequently cleaned up/deleted under R3 because they are empty or short. This leads to duplicate/empty outline links or outline rendering on chapters that have fewer than 3 actual filled sections.
- **Where**: `app.js` lines 581-595.
- **Why**: The outline panel is generated by slicing the first 35 lines of `lines` and extracting matching sections *before* the rendering loop runs. R3 cleaning is done dynamically during the loop, meaning the outline count does not reflect the actual post-cleaning filled sections count.
- **Suggestion**: Postpone outline HTML construction or rewrite the outline panel to use the post-cleaned list of sections.

### [Minor] Finding 4: Unicode Hyphenation Missing Capital Y with Diaeresis (`Ÿ`)
- **What**: The extended hyphenation regex supports French accented uppercase characters but misses `Ÿ` (U+0178).
- **Where**: `app.js` lines 420, 426, 435.
- **Why**: The regex bracket class `[a-zA-Zà-öø-ÿœŒæÆÀ-ÖØ-ß]` includes standard French capital accents (in `À-Ö` and `Ø-ß`) but Y-diaeresis `Ÿ` is located at U+0178, outside these ranges.
- **Suggestion**: Add `Ÿ` to the regex character class explicitly: `[a-zA-Zà-öø-ÿœŒæÆÀ-ÖØ-ßŸ]`.
